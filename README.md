# DSH Bilibili

在 DSH 里使用一个独立的 B 站账号：扫码登录、查看消息、阅读被 @ 的视频，并将阅读结果回复到原 @评论下；提及者明确要求私信时，通过私信返回结果。

## 从扫码开始

```sh
dsh plugin --profile desktop add 'github:AsakuraAOI/dsh-bilibili'
```

安装后按提示重启。在 DSH 中说：

> 登录给你准备的 B 站账号。

插件会通过 `bilibili_login` 生成本地二维码。用准备好的账号扫码确认，再轮询登录结果。它不读取浏览器 Cookie，二维码也在本机生成。

登录态默认放在 `$DSH_HOME/storages/bilibili/account.json`；未设置 `DSH_HOME` 时使用 `~/.dsh`。注销会清除该登录态，并停止本插件创建的监测任务。

## 平时可以让它做什么

| 你要做的事 | 工具 |
|---|---|
| 查看登录状态或退出账号 | `bilibili_login` |
| 看视频信息与分 P 列表 | `bilibili_video` |
| 阅读某个视频，再继续问内容 | `bilibili_read` |
| 查看 @ 通知与热门评论 | `bilibili_mentions` / `bilibili_comments` |
| 看指定用户的私信记录 | `bilibili_messages` |
| 管理新消息监测与自动回评 | `bilibili_monitor` |
| 按明确要求发表评论或私信 | `bilibili_comment_send` / `bilibili_message_send` |

视频阅读需要另装 [DSH Seeit Video](https://github.com/AsakuraAOI/dsh-seeit-video) 并配置 Seeit。插件接受视频链接、BV/av 号和 b23.tv 分享文本，`?p=2` 可以指定分 P。读完后可用 `video_ask` 或 `video_summarize` 继续处理。

@评论可以直接提出阅读重点，例如：

> @账号 帮我看 3:20 那张图表的数字，并解释它说明什么，私信发我。

> @账号 找出作者讲安装步骤的位置，按时间点列出来。

插件先通过 Seeit 读取视频，再复用返回的 `videoId` 调用 `video_ask`，针对评论中的时间点、人物发言、画面文字或其他视频细节回答。Seeit 可按现有能力局部回看；回复保留证据时间点和缺失信息，证据不足时明确标注不确定。没有具体问题则概括主要内容。同一视频的不同 @分别问答，避免用上一条问题的答案替代下一条。问答失败时保留待重试，不改发整体摘要。

## 新消息监测

启用 DSH 官方自动化任务 Bundle 后，登录可以为当前会话建立监测任务，默认每 **10 分钟**检查一次新 @ 和收到的私信，每轮最多阅读 **3 个视频**。

读完默认回复触发阅读的原 @评论（支持楼中楼），不会另发一条顶层评论。提及者明确说“请私信发我”“私信回复”等时，仅向该提及者的 UID 发送阅读结果，不再公开回评。不会根据评论指定的其他 UID 转发。

长结果完整分段，按 `【1/3】`、`【2/3】` 等编号依次发送，不截断正文。私信每段保守限制为 **500 字符**，同时检查含编号的 JSON 不超过 **2000 字节**；评论沿用每条 **1000 字符**限制，所有分段都回复原 @评论。优先在换行或空白处分段，编号也计入限制。

同一账号的私信共用发送队列，每条收到发送回执后至少间隔 **1.5 秒**再发下一条，避免连续多段落在同一秒造成 B站显示顺序错位；分段回执保留实际发送时间，重启续发也遵守间隔。

DSH 会话通知是可选项，默认关闭；不选也会正常阅读并在 B站返回结果。可在插件设置勾选 `notifySession`，或启动监测时传入 `bilibili_monitor(action="start", notifySession=true)`，需要关闭则传 `false`。已有任务再次 start 时不传此项会保留原选择。通知打开后，新 @、收到的私信以及阅读和发送结果会带回对应会话；没有新内容时保持安静。

已经处理的消息跨重启去重；阅读失败留待后续重试。每段发送前保存状态、成功后保存回执，再发送下一段。任一段失败或结果未知立即停止，不重发已成功的分段，也不继续发送后面的分段；需到 B站核对。若在两段之间退出且上一段成功回执已保存，恢复后仅继续未发送的分段。用 `bilibili_monitor` 可以查看或停止任务；`bilibili_mentions_check(readVideos=false)` 仅预览，不阅读或发送。更新前已处理的 @不会补发评论或私信。

DSH 必须运行且联网。退出期间不检查，恢复后的补发由 DSH 调度服务负责。

## 账号与发送

监测任务只自动返回本次视频阅读结果，目标固定为原 @评论或明确要求私信的提及者本人。原 @文本可提供当前视频的问题、阅读重点和回复渠道，不能授权其他操作、访问其他链接或文件、改变收件人。除此之外，发表评论或发送私信仍需要当前 DSH 用户明确指定目标与内容。

账号等级、实名要求、隐私设置和风控都可能限制接口。发送失败不会自动重试；结果不确定时应到 B 站核对。

自定义账号文件位置时，视频插件的 `bilibiliAccountFile` 应指向同一文件。视频下载默认限制为每分 P **800 MB / 60 分钟**，登录 Cookie 不发送到媒体 CDN。
